نموذج أولي عربي يحول بيانات الشموع `OHLCV` إلى رسم شموع وقرار **شراء / بيع / انتظار**، مع عرض سبب تحقق أو عدم تحقق الشروط. كما يعرض شارت TradingView للرمز نفسه كمرجع بصري مستقل.

## التشغيل مع الخادم الخلفي التجريبي

```powershell
npm start
```

ثم افتح `http://127.0.0.1:8080`. الصفحة الافتراضية هي `index-production.html`، وتستخدم `/api/analyze` للاتصال بالمصدرين.

الخادم يستخدم صفحة المجموعة للتحقق من رمز الشركة واسمها، وواجهة TradingView الداخلية غير الموثقة لاسترجاع السعر والمؤشرات. هذا مناسب للتجربة فقط وقد تتغير الواجهة دون إشعار. لا يعيد نشر بث Lightstreamer اللحظي للمجموعة.

## GitHub Pages مع Vercel

1. ارفع المشروع إلى مستودع GitHub.
2. في Vercel اختر **Add New Project** ثم استورد المستودع وانشره دون Build Command.
3. انسخ رابط Vercel، ثم ضعه في `API_BASE` داخل `index-production.html`.
4. انسخ محتوى `index-production.html` إلى `index.html` المستخدم في GitHub Pages.
5. أعد رفع التغيير إلى GitHub.

لزيادة الأمان، أضف متغير بيئة في Vercel باسم `ALLOWED_ORIGIN` وقيمته رابط GitHub Pages الكامل، مثل `https://username.github.io`.

## تشغيل الواجهة القديمة فقط

يجب تشغيل الملفات عبر خادم محلي لأن JavaScript يستخدم ES Modules:

```powershell
python -m http.server 8080
```

ثم افتح `http://localhost:8080`.

## إدخال بيانات حقيقية

ارفع ملف CSV مرتبًا زمنيًا ويحتوي على 60 صفًا على الأقل:

```csv
date,open,high,low,close,volume
2026-01-04,14.10,14.35,14.02,14.28,1250000
```

الوضع الافتراضي يستخدم بيانات مولدة للاختبار، وليست أسعارًا حية.

## تحويل شروط الدورة إلى أرقام

- الاتجاه الصاعد: الإغلاق أعلى SMA20 وSMA20 أعلى SMA50.
- الاتجاه الهابط: الإغلاق أدنى SMA20 وSMA20 أدنى SMA50.
- حجم مرتفع: 1.5 مرة أو أكثر من متوسط حجم 20 شمعة.
- شمعة طويلة: تغير جسم الشمعة 3% أو أكثر.
- انفجار سعري: تغير جسم الشمعة 6% أو أكثر.
- RSI: فترة 14.
- القمم والقيعان: Pivot بعرض 3 شموع يمينًا ويسارًا.
- الكسر/الاختراق الوهمي: تجاوز أعلى/أدنى 20 شمعة ثم الإغلاق داخل النطاق.
- تأكيد الشراء: شمعة صاعدة تغلق أعلى قمة الشمعة السابقة.
- تأكيد البيع: شمعة هابطة تغلق أدنى قاع الشمعة السابقة.
- حد القرار: 60 نقطة من 100.

جميع القيم موجودة في `analysis-engine.js` ويمكن تعديلها بعد الاختبار التاريخي.

## ما يلزم للإنتاج

1. اتفاق رسمي أو API مرخص لبيانات بورصة قطر التاريخية واللحظية.
2. موصل خادم يحول البيانات إلى مخطط `OHLCV` موحد.
3. اختبار تاريخي Walk-forward لكل سهم وإطار زمني.
4. إضافة تكاليف التداول والانزلاق وحدود السيولة.
5. نشر HTTPS ومراقبة انقطاع أو تأخر مصدر البيانات.

> هذه أداة تحليل تعليمية وليست توصية مالية أو ضمانًا للربح.
